# Asteroids

Аркадна гра для браузера: ухиляйся від астероїдів, збирай кристали, пройди 25 рівнів кампанії або встанови рекорд у режимі виживання.

Це веб-версія курсової роботи з ООП. Оригінал був написаний на C# / WinForms і повністю переписаний на **TypeScript + Canvas 2D**. Гра працює на комп'ютері (клавіатура) і на телефоні (сенсорний джойстик).

## Запуск локально

```bash
npm install
npm run dev       # дев-сервер з hot reload
npm run build     # продакшн-збірка в dist/
npm run preview   # перегляд зібраної версії
```

### Сервер (онлайн, PvP, профіль)

```bash
docker compose up -d          # MongoDB
cd server && npm install
npm run dev                   # усі мікросервіси й 2 ігрові сервери одною командою (GAME_SERVERS=4 — більше)
npm run net:check             # перевірка влучань і компенсації лагу на живому сервері
```

Повністю в контейнерах: `docker compose --profile full up --build` (шлюз на :8787).

## Архітектура сервера

```
                        ┌──────────── gateway :8787 ─────────────┐
 браузер ── HTTP /api ──┤ маршрутизація за префіксом шляху       │
         ── WS /socket.io ─► matchmaker      ── WS /game/<id> ─► game-сервер з реєстру
                        └────────────────────────────────────────┘
   auth :8801      реєстрація, вхід, JWT
   profile :8802   профіль, прокачка, спорядження, кампанія, щоденні, квести, пропуск; записує результати PvP
   shop :8803      покупки: предмети, зброя, літаки, преміум-пропуск
   crates :8804    ящики
   stats :8805     таблиці лідерів
   social :8806    друзі, групи, присутність (онлайн / у бою)
   matchmaker :8807  черги (socket.io), реєстр ігрових серверів, квитки на матч
   game ×N :8901+  симуляція матчів, чистий WebSocket, без бази даних
```

- **Шлюз** — єдина точка входу; `/internal/*` назовні не видно. `GET /api/health` — стан усіх сервісів, `GET /api/metrics` — черги й метрики ігрових серверів.
- **Між сервісами** — HTTP `/internal/*` із токеном `INTERNAL_TOKEN`, таймаутом і повторами. Ігровий сервер шле результати матчу сервісу профілю (ідемпотентно за id матчу), присутність — соціальному сервісу.
- **Матч**: матчмейкер збирає кімнату (групи — цілими), обирає найменш завантажений ігровий сервер, створює там кімнату й видає гравцям підписаний квиток (`GAME_TICKET_SECRET`, 2 хв). Клієнт підʼєднується до ігрового сервера через шлюз.
- **Мережа бою**: тік 30 Гц; бінарний протокол із дельта-компресією (`server/src/shared/netcodec.ts`, спільний для сервера й клієнта); інтерполяція чужих літаків на клієнті (100 мс); влучання рахує лише сервер із компенсацією лагу (історія позицій, до 300 мс); анти-чит темпу стрільби й швидкості руху.
- **Дані**: одна MongoDB, але кожен сервіс пише лише свої поля (профіль — прогрес і нагороди, магазин — покупки, соціальний — друзі). Розділення на окремі бази — наступний крок, коли знадобиться.
- **Масштабування**: ігрових серверів — скільки завгодно (кожен реєструється в матчмейкері сам); решта сервісів без стану, крім social (групи й присутність у памʼяті — один екземпляр).

### Навантаження

`npm run loadtest -- --clients 300 --seconds 30` — мережеві боти проходять увесь шлях гравця (черга → квиток → бій) і 30 разів на секунду шлють рух і постріли. Заміри на одній машині (2 ігрові процеси, генератор навантаження там само):

| Гравців | Кімнат | Тік кімнати | Бюджет тіку процесу | CPU ігрового процесу | Трафік на гравця |
|---|---|---|---|---|---|
| 100 | 10 | 0.68 мс | 12% | 8–13% ядра | 3.6 КБ/с |
| 300 | 30 | 0.59 мс | 27% | 27–29% ядра | 3.8 КБ/с |

Бюджет тіку — 33 мс (30 Гц), одна кімната з 10 гравцями коштує ~0.6 мс: це ~33 кімнати (~330 гравців) на ядро з 40% запасу. Процесор не вузьке місце, тож симуляцію на Rust не переписуємо — масштабуємось кількістю ігрових процесів (`GAME_SERVERS=N`). Скрипт сам підкаже, якщо колись симуляція почне зʼїдати понад 60% бюджету тіку. Затримка event loop p99 ~17–22 мс — це крок системного таймера Windows (~15.6 мс), на Linux вона на порядок менша.

## Деплой

У `dist/` лежать звичайні статичні файли, тому їх можна викласти на будь-який хостинг.

- **GitHub Pages**: workflow `.github/workflows/deploy.yml` збирає й публікує гру при кожному push у `main`. Один раз потрібно ввімкнути: *Settings → Pages → Source: GitHub Actions*.
- **Vercel / Netlify**: імпортуй репозиторій. Build command: `npm run build`, output directory: `dist`.
- **itch.io**: заархівуй вміст `dist/` у zip і завантаж як HTML-гру.

## Що змінилось порівняно з WinForms-версією

**Геймплей**
- 25 рівнів замість 5, поділених на 5 секторів.
- 11 типів небезпек, що з'являються поступово:
  - комети з попередженням-траєкторією;
  - самонавідні «мисливці»;
  - рикошетні астероїди;
  - «стіни» з проходом;
  - метеоритний дощ;
  - туман;
  - міни з ланцюговими вибухами;
  - сонячний вітер;
  - чорні діри;
  - лазерні бар'єри;
  - бос-астероїд.
- Кристали й зірки (до 3 за рівень), бонуси: щит, заряди заморозки й форсажу.
- 11 літаків різної форми, кожен зі своєю фічею: таран, магніт, подвійний ривок, ударна хвиля, друге життя, антигравітація тощо.
- Валюта **коінс**. Як заробити:
  - кристали: +5 за кожен;
  - проходження рівня: база плюс бонус за зірки, за перше проходження вдвічі більше;
  - час у виживанні;
  - щоденна нагорода: серія з 7 днів, від 50 до 500 коінс.
- За коінс в ангарі купуються нові літаки.
- Відлік 3-2-1 перед стартом і підказка про нову небезпеку рівня.
- Виживання: складність росте кожні 10 с, нові небезпеки відкриваються з часом, топ-5 результатів.

**Виправлені баги**
- Тертя множилось на кожному кадрі без урахування `dt`: швидкість літака залежала від FPS і реально була ~100 px/s замість 320.
- Програш у кампанії скидав *увесь* прогрес. Тепер можна просто повторити рівень.
- Рівні тривали лише `level * 10` секунд (перший рівень — 10 с).
- Астероїди з'являлись уже всередині екрана (відступ 10 px при радіусі спрайта до 42 px).
- Астероїд міг з'явитись впритул до літака, притиснутого до краю.
- Клавіші «залипали» після втрати фокусу вікна; гра не ставала на паузу.
- Назви скінів (`Red/Blue/Green`) не відповідали картинкам.
- Фіксований крок фізики (1/120 с): швидкі об'єкти не «проскакують» крізь літак.

**Інтерфейс**
- Анімоване меню з живим фоном, навігація з клавіатури, модальні вікна, HUD з таймером, прогресом і перезарядкою навичок.
- Українська та англійська мови, гучність, тряска екрана, скидання прогресу.
- Звуки синтезуються через WebAudio, тож аудіофайли не потрібні.
- Адаптивна верстка й сенсорне керування.

## Структура

```
src/
  core/      математика, ресурси, введення, звук, збереження, i18n
  game/      Game (ігровий менеджер), рівні, літаки
    entities/  Entity → Asteroid → HomingAsteroid / BouncingAsteroid / Comet / BlackHole / BossAsteroid,
               Mine, LaserGate, Player, Pickup
    systems/   SkillSystem, ParticleSystem, Starfield
  ui/        екрани (Screen → MainMenu, LevelSelect, Hangar, …), модалки, HUD
  app/       App: canvas, ігровий цикл, перемикання екранів
```

Усі 11 літаків намальовані кодом на Canvas (`src/game/PlaneArt.ts`): металеві градієнти, кабіни, сопла, навігаційні вогні й анімовані деталі. Статичний корпус кешується в offscreen-canvas.

Шрифт логотипа — [Bungee](https://github.com/djrrb/Bungee) (SIL OFL 1.1).
